## Task 4: `astFindingId` + `changedLines` builder + reviewable-position resolver — TDD

**Files:** `src/lib/ast-rules/finding-id.ts`, `src/lib/ast-rules/diff-filter.ts`, `tests/ast-rules-diff-filter.test.ts`

- [ ] `finding-id.ts`: `astFindingId(ruleId, path, line): string` — Web-Crypto SHA-256 over `path`, take 7 hex chars, format `ast/${ruleId}/${pathHash7}/${line}`. Pure async function.
- [ ] `diff-filter.ts`:
  - `buildChangedLines(diff: string): Map<path, Set<number>>` — **only `+` (new-side) lines** of the unified diff, keyed by new-file path. **`-` (old-side) lines are NOT counted** (Codex MAJOR #6 tightening). Replacement hunks contribute the new-side numeric line of each `+` line; the matching `-` line on the old side is ignored. Pure-deletion hunks contribute nothing on the new side.
  - `nodeOverlapsChanged(node, changedLines): boolean` — checks whether `[node.loc.start.line, node.loc.end.line]` intersects the set.
  - `findReviewPosition(reviewable: ReviewableMap, path: string, line: number): { line, side: "RIGHT" } | null` — wraps the existing `parseDiffToReviewablePositions` output for findings that may auto-post.
- [ ] **Tests (multi-line span)**:
  - Single-line node, line in changed set → kept.
  - Single-line node, line NOT in changed set → dropped.
  - Multi-line node `[10..15]`, only line 12 in changed set → kept (intersection non-empty).
  - Multi-line node entirely outside changed set → dropped.
  - **Replacement hunk** (one `-` then one `+` on consecutive numeric lines) → only the `+` new-side line is in `changedLines`; the `-` old-side line is NOT counted (regression test for Codex MAJOR #6).
  - **Pure-deletion hunk** (only `-` lines) → no entries added to `changedLines` for that path.
  - Findings whose path has no changed lines at all → dropped.
- [ ] Commit: `feat(arc-181): astFindingId + new-side-only changedLines diff filter + review-position resolver`

## Task 10: remaining 9 rules + ALL_RULES registry update — TDD batch

**Files:** `src/lib/ast-rules/rules/{spawn-shell-true,no-disabled-tls-reject-unauthorized,no-document-write-call,no-new-function-constructor,no-async-without-await,no-throw-literal,no-await-in-loop,no-floating-promise-call-known-async,no-process-env-mutation}.ts`, plus per-rule test file each.

Each rule gets 3+ positive + 3+ negative fixtures. Implementation patterns:

- [ ] **`no-new-function-constructor`** — `NewExpression` with `callee.type === "Identifier" && callee.name === "Function"`.
- [ ] **`spawn-shell-true`** — `CallExpression` whose `callee` is `spawn`/`spawnSync`/`execFile`/`execFileSync` (Identifier OR `MemberExpression` with `.spawn` etc) AND has an options object argument with `shell: true` literal.
- [ ] **`no-disabled-tls-reject-unauthorized`** — any `ObjectExpression` containing a `Property` with `key.name === "rejectUnauthorized" && value.value === false`.
- [ ] **`no-document-write-call`** — `CallExpression` with `callee.object.name === "document" && (callee.property.name === "write" || "writeln")`.
- [ ] **`no-async-without-await`** — `FunctionDeclaration`/`FunctionExpression`/`ArrowFunctionExpression` with `async: true` and no `AwaitExpression` descendant in the body (recursive walk).
- [ ] **`no-throw-literal`** — `ThrowStatement` whose `argument.type` is `Literal` (string/number) or `TemplateLiteral` with no `Identifier`/`Expression` parts.
- [ ] **`no-await-in-loop`** — `AwaitExpression` whose ancestor chain includes any `ForStatement`/`ForInStatement`/`ForOfStatement`/`WhileStatement`/`DoWhileStatement` (without crossing a function boundary).
- [ ] **`no-floating-promise-call-known-async`** — `ExpressionStatement` whose `expression.type === "CallExpression"` AND the called identifier resolves to a same-file `async function` declaration. Uses a pre-pass map of `{ identifierName → "async-fn" | "non-async-fn" | "unknown" }`. **Pre-pass is rule-internal** (Kimi MINOR #4): the rule's `visit()` initializer walks the file's top-level once to build the map before traversal; no runner-side hook needed. Self-contained commit.
- [ ] **`no-process-env-mutation`** — `AssignmentExpression` with `left.type === "MemberExpression"` and `left.object.object.name === "process" && left.object.property.name === "env"`.
- [ ] Per-rule test file with 3+ positive + 3+ negative fixtures each (60+ micro-tests across the pack).
- [ ] **`ALL_RULES` registry update** (Codex MAJOR #3): `rule-registry.ts` exports the full 10-rule array. Test: `expect(ALL_RULES.map(r => r.id)).toEqual(["no-eval-call", "no-new-function-constructor", "spawn-shell-true", "no-disabled-tls-reject-unauthorized", "no-document-write-call", "no-async-without-await", "no-throw-literal", "no-await-in-loop", "no-floating-promise-call-known-async", "no-process-env-mutation"])`. Per-rule severity + roleHint also asserted (locks the contract for the rule pack).
- [ ] Commit: `feat(arc-181): 9 additional rules complete the v1 rule pack + ALL_RULES contract test (60+ fixture tests)`
